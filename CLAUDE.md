# tubele

A server-driven Rust port of Tubele, a daily London station guessing game: axum, askama, Datastar and Tailwind, with state in SQLite. It ships as the image `ghcr.io/radiosilence/tubele-rs` and the Pulumi component `@radiosilence/tubele-pulumi` in `deploy/pulumi`, which share one version; jaritanet deploys it at tubele.blit.cc by pinning that package.

## The one rule

No answer reaches the browser before its board is finished. The answer station enters a template only through `view::ResultView`, which is built only for a finished board; `an_unfinished_board_never_names_the_answer` guards it. Search, clues and feedback are computed server-side. Keep it that way: no endpoint may take a puzzle number the player has not already started, and practice never draws from the next seven days' answers.

## Git

- Work in PRs. PRs are squashed; merge main into a branch rather than rebasing.
- Releases go through `just release`, never a hand-edited version on main. Never push tags; CI tags and publishes when a release PR merges.
- Commits are signed.

## Changelog

`CHANGELOG.md` is generated by `scripts/changelog.py` and never edited by hand. Every change adds one fragment under `changelog.d/unreleased/<section>/`, named `<pr>-<slug>.md` and holding one `- **Lead.** Detail.` entry. The format is in `changelog.d/README.md`.

## Releasing

`just release patch|minor|major` (or an exact `X.Y.Z`) branches from main, bumps `Cargo.toml` and `Cargo.lock`, `deploy/pulumi/package.json` and its lockfile, and `APP_VERSION` in `deploy/pulumi/src/versions.ts`, turns the unreleased fragments into the version and opens the release PR. Merging it is the release: CI pushes the image's semver tags, publishes the Pulumi package, then creates the GitHub release. `gh workflow run ci-cd.yml` on main retries a release that failed part way. Both need the `RELEASE_TOKEN` secret.

## CI/CD

`.github/workflows/ci-cd.yml` is one pipeline, the same shape as slsk-mcp's. CI ends in `Checks`, the only status a ruleset should require; CD runs after it on main. The `changes` job decides from the diff which domains a change touches (`rust`, `web`, `package`, `docker`, `deps`), as allowlists of paths: a new top-level directory of code needs adding to its domain. The static musl binaries are built once per architecture and the `scratch` image only copies them in.

## Check

```sh
just check   # Cargo.lock clean, fmt, clippy -D warnings, tests, the Pulumi package, stylesheet fresh, changelog, versions
just css     # after changing styles/, a template or class strings in src/
```

## Frontend

- Tailwind v4, standalone CLI from mise. Tokens are in `styles/app.css`; class names written in Rust must be literal strings so Tailwind's `@source "../src"` finds them.
- The CSP has no `unsafe-inline`: no `style=""` and no inline scripts. Line colours come from the generated `/assets/lines.css`; elements that start hidden use the `hidden` attribute with `data-attr:hidden`, not `data-show`, so they do not flash before Datastar loads.
- `assets/app.js` is plain JavaScript with no build step. It is served with its `./datastar.js` import rewritten to the fingerprinted URL, so the page has one Datastar instance.
